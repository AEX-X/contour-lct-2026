# Contour

Frontend-прототип центра управления инженерной инфраструктурой для задачи ЛЦТ 2026 АО «Москоллектор»

Проект показывает единый процесс от прогнозного риска и заявки диспетчера до назначения инженера, офлайн-работы, проверки ремонта и закрытия заявки

## Что реализовано

- Ролевая модель для руководителя, старшего диспетчера, диспетчера объекта, координатора ремонтов и инженера
- Городская карта объектов со статусами, поиском, фильтрами и очередью внимания
- Карточка предприятия с оборудованием, датчиками, рисками и заявками
- Управленческая, техническая и финансовая аналитика
- Очередь координатора с триажем, SLA, загрузкой и назначением инженеров
- Полный жизненный цикл ремонтной заявки
- Временный доступ инженера к техническому контексту объекта
- Офлайн-пакет, локальный отчёт, очередь синхронизации и обработка конфликтов
- Адаптивные рабочие места для настольного компьютера, планшета и телефона
- Журнал аудита и уведомления

Все содержательные данные синтетические. Геометрия карты, телеметрия, финансовые показатели и история ремонтов не являются реальными данными АО «Москоллектор»

## Режимы данных

По умолчанию приложение запускается в автономном режиме `mock`. Он не зависит от backend и воспроизводит полный пяти-ролевой сценарий для демонстрации

Дополнительно реализован режим `api`, который подключается к текущему FastAPI backend команды. Режим выбирается только при сборке или запуске и всегда виден в интерфейсе. Скрытого смешивания API и mock-сущностей нет

```dotenv
VITE_CONTOUR_DATA_MODE=api
VITE_CONTOUR_API_BASE_URL=/api/v1
CONTOUR_API_PROXY_TARGET=https://localhost:8443
```

Последняя переменная используется только локальным Vite proxy и не попадает в клиентскую сборку. В production рекомендуется публиковать frontend и `/api` на одном HTTPS origin

API-режим сейчас поддерживает:

- серверную авторизацию и завершение сессии
- права и область доступа из `/me`
- объекты, демонстрационные координаты и иерархию
- схему объекта, оборудование из иерархии, датчики и числовые ряды
- события, подтверждённые инциденты и прогнозные риски
- принятие прогнозного риска в работу с контролем версии
- список и создание черновика заявки
- backend-аудит и вычисляемые операционные KPI

Текущий backend не предоставляет ручной жизненный цикл заявок, назначения инженеров, уведомления и управление закреплением диспетчеров. В API-режиме эти операции не симулируются. Полный расширенный процесс остаётся доступен в автономном `mock`-режиме

Пример конфигурации находится в `.env.example`. Пароли и session token в файлы окружения не записываются. Token хранится только в `sessionStorage`, пароль после запроса не сохраняется

## Структура

```text
src/app            маршрутизация, оболочка, роли и запросы
src/domain         типы, права доступа и селекторы
src/repositories   контракт данных и демонстрационный репозиторий
src/mocks          детерминированный синтетический сценарий
src/offline        офлайн-пакеты, очередь изменений и синхронизация
src/pages          продуктовые экраны
src/shared/ui      дизайн-система и переиспользуемые компоненты
src/styles         токены, глобальные правила и компоненты
```

UI не зависит напрямую от формата хранения данных. Автономный сценарий реализует `MockContourRepository`, а интеграционный режим использует отдельный типизированный `ApiContourRepository`. Ответы backend проверяются Zod-схемами, поэтому несовместимый контракт не превращается в правдоподобные, но неверные данные интерфейса

## Демо-сценарий

Роль меняется через меню профиля в правом верхнем углу. Все роли используют одно общее состояние, поэтому действие в одной роли сразу появляется в другой

Исходный сценарий можно восстановить пунктом «Сбросить сценарий» в меню профиля
